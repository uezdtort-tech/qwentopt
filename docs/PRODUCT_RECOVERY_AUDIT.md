## 2. Текущее состояние Qwentopt (локальная копия)

### 2.1. Архитектура

**Стек:**
- Frontend: React 18 + TypeScript + Vite
- Стилизация: Tailwind CSS 4
- Маршрутизация: React Router DOM 6
- Состояние: React Context API (локальное)
- Данные: Mock-данные в памяти (без persistence)

**Точки входа:**
- Frontend: `src/main.tsx` → `src/App.tsx`
- Backend: ❌ Отсутствует
- API: ❌ Отсутствует
- База данных: ❌ Отсутствует (только mock-данные)

### 2.2. Маршруты

**Публичная часть:**
```
/                    → HomePage (главная страница)
/catalog             → CatalogPage (каталог товаров)
/product/:id         → ProductPage (карточка товара)
/b2b                 → B2BPage (профессиональные партнёры)
/events              → EventPlannerPage (планировщик мероприятий)
/chat                → ChatPage (чат с кондитером)
/auth                → AuthPage (авторизация)

```

**Кабинет кондитера:**
```
/dashboard           → DashboardPage (обзор)
/dashboard/orders    → OrdersPage (заказы)

/dashboard/ai        → AIAssistantPage (AI-помощник)
```

### 2.3. Управление состоянием

**AppContext.tsx:**
- Использует `useState` для локального состояния
- **Данные хранятся ТОЛЬКО в памяти React**
- При перезагрузке страницы все данные теряются
- Нет интеграции с Supabase или любым другим бэкендом

**Состояние включает:**
```typescript
interface AppState {
  isAuthenticated: boolean;        // ❌ Без реальной авторизации
  userRole: 'guest' | 'buyer' | 'seller' | 'admin';  // ❌ Без проверки прав
  userName: string;                // ❌ Mock-имена
  currentView: 'public' | 'dashboard';
  orders: Order[];                 // ❌ Пустой массив, не связан с БД
  messages: ChatMessage[];         // ❌ Mock-сообщения из mockData.ts
  notifications: number;           // ❌ Захардкожено значение 3
  cart: CartItem[];                // ❌ Только в памяти
}
```

**Критические проблемы:**
1. ❌ Авторизация имитируется без реальной проверки
2. ❌ Роли не проверяются на сервере
3. ❌ Данные не сохраняются между сессиями
4. ❌ Нет изоляции данных пользователей
5. ❌ Нет серверной валидации

### 2.4. Mock-данные

**Файл:** `src/data/mockData.ts`

**Содержит:**
- 8 товаров (торты, пирожные)
- 6 заказов с разными статусами
- 2 рецепта с ингредиентами
- 10 позиций склада
- 5 покупателей
- 5 B2B-партнёров
- 2 мероприятия с задачами
- 5 сообщений чата

**Проблемы:**
- ❌ Данные захардкожены
- ❌ Не связаны с реальной БД
- ❌ Не могут быть изменены пользователем
- ❌ Не проходят через серверную валидацию
- ❌ Не имеют истории изменений

### 2.5. Интеграции

**Supabase:**
- ❌ Не настроен
- ❌ Нет подключения в коде
- ⚠️ Есть заготовки в `src/services/supabaseAuth.ts`, но не используются
- ⚠️ Есть `src/vite-env.d.ts` с типами для Supabase, но переменные не заданы

**OAuth (Яндекс ID, VK ID):**

- ✅ Реализован OAuth flow с PKCE

- ❌ Не протестировано с реальными приложениями
- ❌ Требуется регистрация в кабинетах провайдеров

**Ollama (AI):**
- ❌ Не подключена
- ⚠️ Есть UI AI-помощника с mock-ответами
- ❌ Нет реальных запросов к локальной модели

**n8n:**
- ❌ Не подключена
- ❌ Нет отправки событий
- ❌ Нет обработки webhook

**Платёжный провайдер:**
- ❌ Отсутствует
- ⚠️ В FinancePage показаны mock-данные о выручке
- ❌ Нет реальных платежей

### 2.6. Авторизация и безопасность

**Текущая реализация:**
```typescript
const login = (role: 'buyer' | 'seller' | 'admin') => {
  const names = { buyer: 'Мария Иванова', seller: 'Анна Пекарская', admin: 'Администратор' };
  setState(s => ({ ...s, isAuthenticated: true, userRole: role, userName: names[role] }));
};
```

**Проблемы безопасности:**
1. ❌ Нет реальной проверки учётных данных
2. ❌ Роль выбирается пользователем на клиенте
3. ❌ Нет server-side validation
4. ❌ Нет RLS (Row Level Security)
5. ❌ Нет защиты от IDOR
6. ❌ Нет rate limiting
7. ❌ Нет аудита действий

**OAuth:**
- ✅ PKCE реализован
- ✅ State parameter реализован
- ⚠️ Client secret не используется (только для серверного flow)
- ❌ Token exchange на клиенте (требует переноса на сервер)

## 5. Выводы

### 5.1. Qwentopt — это UI-прототип

**Подтверждено кодом:**
- Все данные в `mockData.ts` захардкожены
- `AppContext` использует только `useState`
- Нет вызовов к Supabase API
- Нет серверной логики
- Нет миграций БД

**Статус:** ❌ Не является production-ready продуктом

### 5.2. Qwentopt содержит полезные UI-решения

**Что можно использовать:**
1. ✅ Дизайн-система (цвета, типографика, компоненты)
2. ✅ Структура страниц (Layout, Sidebar)
3. ✅ OAuth UI (кнопки, callback page)
4. ✅ Адаптивная вёрстка
5. ✅ UX-паттерны (фильтры каталога, формы)

**Что НЕЛЬЗЯ переносить:**
1. ❌ Mock-данные
2. ❌ Клиентская бизнес-логика
3. ❌ Имитация авторизации
4. ❌ Отсутствие серверной валидации

### 5.3. Conditera остаётся основой

**Обоснование:**
- Содержит реальную бизнес-логику
- Имеет интеграцию с Supabase
- Имеет тесты (предположительно)
